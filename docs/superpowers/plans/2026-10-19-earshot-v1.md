# Earshot v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Swift terminal tool `earshot` that lists every Claude Code session running in Apple Terminal tabs, types push-to-talk speech into the focused tab, and reads a session's final reply aloud on demand with a natural local voice.

**Architecture:** Claude Code hooks run `earshot hook`, which appends one JSON line per event (with the Claude process's TTY) to an event log. The dashboard (`earshot`) tails that log, keeps a session state machine, maps TTYs to Terminal tabs via AppleScript, and runs hotkey, mic, STT and TTS in-process so macOS attributes every permission to Terminal.app.

**Tech Stack:** Swift 6.3 / SwiftPM, swift-testing, FluidAudio 0.17.x (Parakeet STT, Kokoro TTS), AVFoundation, CoreGraphics event taps, NSAppleScript. No TUI library (hand-rolled ANSI).

**Spec:** `docs/superpowers/specs/2026-10-19-earshot-design.md`

## Global Constraints

- macOS 26, Apple Silicon. `platforms: [.macOS(.v15)]` minimum (Kokoro ANE v3 needs macOS 15).
- `swiftLanguageModes: [.v5]` for all targets (avoid strict-concurrency churn in a CFRunLoop/AV app).
- Only dependency: `https://github.com/FluidInference/FluidAudio.git` `from: "0.17.7"`, product `FluidAudio`, only in target `EarshotVoice`.
- English only: STT `AsrModels.downloadAndLoad(version: .v2)`; TTS `KokoroAneManager(version: .v3)`, default voice `af_heart`.
- Nothing plays and no tab switches on its own. Finish sound is the only automatic output.
- Spoken text is typed without Enter unless `autoSend` is true.
- Never type into a tab that is not a known Claude session, and never into the dashboard's own tab.
- Earshot never reads `~/.claude/.credentials*`, keychain, or tokens. Summary mode only invokes the `claude` CLI.
- Nothing leaves the machine except FluidAudio's one-time model downloads.
- `earshot hook` must always exit 0, never print to stdout, and finish in under 100 ms.
- Event log: `~/Library/Application Support/Earshot/events.jsonl`. Config: `~/.config/earshot/config.json`.
- Internal `claude -p` runs set env `EARSHOT_INTERNAL=1`; `earshot hook` drops events when it is set.
- Commits: no `Co-Authored-By` trailer (owner rule).

## Review Focus

1. Owner's `~/.claude/settings.json` already has other keys (env, permissions, plugins, statusLine) and may later have other hooks on the same events — install/uninstall must keep all of them (Task 3 test `preservesForeignHooksAndKeys`).
2. `earshot hook` run when the Earshot support dir does not exist or is unwritable — must exit 0 silently (Task 1 test `hookNeverFailsOnUnwritableLog`).
3. Owner quits `claude` and starts a new one in the same tab — the old row is replaced, not duplicated (Task 2 test `newSessionOnSameTTYReplacesOld`).
4. Owner switches tabs while still holding the hotkey, or releases while the dashboard window is frontmost — text goes to the tab focused at release, or nowhere (Task 8 test `routeUsesFocusAtRelease`, `routeRefusesDashboardTab`).
5. Very long reply (thousands of words, many code blocks) — first audio within ~2 s and `p` stops instantly; no chunk exceeds Kokoro's 510-phoneme cap (Task 4 test `chunksNeverExceedLimit`; Task 7 on-device check).

### Task 2: Session state machine

**Files:**
- Create: `Sources/EarshotCore/SessionStore.swift`
- Test: `Tests/EarshotCoreTests/SessionStoreTests.swift`

**Interfaces:**
- Consumes: `HookEvent`, `EventKind` (Task 1).
- Produces:
  - `enum SessionStatus: Equatable { case idle, working, finished, waiting }`
  - `struct Session: Equatable { let id: String; var cwd: String; var tty: String?; var status: SessionStatus; var unread: Bool; var reply: String?; var changedAt: Date; var project: String { last path component of cwd } }`
  - `final class SessionStore { private(set) var sessions: [Session]; func apply(_ e: HookEvent); func markRead(id: String); func prune(liveTTYs: Set<String>); func session(forTTY: String) -> Session? }` — `sessions` sorted by `changedAt` descending.

Rules (exact):
- `SessionStart` → insert/update, status `.idle`. Any other session with the same non-nil `tty` is removed.
- `UserPromptSubmit` → `.working`, `unread = false`.
- `Stop` → `.finished`, `unread = true`, `reply = lastMessage` (keep previous reply if nil).
- `Notification` with type in `permission_prompt, elicitation_dialog, elicitation_url_dialog, agent_needs_input` → `.waiting`. Other types → no change.
- `SessionEnd` → remove.
- Event for an unknown session id (Earshot started mid-session) → create it with the status that event implies.
- `prune(liveTTYs:)` removes sessions whose tty is non-nil and not in the set.
- Every applied event updates `changedAt = e.time`, `cwd`, and `tty` (if non-nil).
