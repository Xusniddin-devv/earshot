## Task 1 — Background-job sessions map to their tab (session registry)

Problem: when a Claude Code session runs as a background job, its hooks report the job's hidden pty
(e.g. /dev/ttys011, process `claude bg-spare`), not the Terminal tab the user sees. The tab runs a plain
`claude` client. So the dashboard prunes or mislabels that session.

Claude Code keeps a live registry: `~/.claude/sessions/<pid>.json`, one per claude process, e.g.
```
{"pid":41001,"sessionId":"aaaa1111-…","kind":"interactive","status":"idle","name":"my-project","parkedJobId":"bbbb2222", …}
{"pid":42002,"sessionId":"bbbb2222-cccc-…","kind":"bg","status":"busy","name":"voice tool","jobId":"bbbb2222", …}
```
The interactive client on the visible tab has `parkedJobId` = the job's short id; the bg process has
`jobId` = same short id and `sessionId` = the session id the hooks report. Some files can contain
trailing garbage (two JSON objects back to back) — parse the first object, skip unreadable files.
This format is undocumented: everything must degrade to current behaviour if the dir is missing or the
shape changes.

Build:
- EarshotCore `SessionRegistry`: parse registry entries (pure, from Data) and compute
  `ttyOverrides: [sessionId: visibleTTY]` given entries plus a `pid -> tty` lookup: for each bg entry
  with jobId J, find an interactive entry with parkedJobId J; map bg.sessionId -> tty(interactive.pid).
- Live loader in EarshotMac or earshot (reads dir, uses `ps -o tty= -p` or sysctl for pid tty).
- Apply in App refresh: before pruning, rewrite each store session's tty using the overrides, so the
  row shows under the visible tab, `@` marks it when focused, Enter jumps to that tab, and it is not
  pruned. Keep the "claude must run on the tab" check (the client is `claude`).
- Tests: parsing (incl. trailing garbage, missing fields), mapping (no match, multiple), store
  integration.

## Task 2 — More accurate status

- Add hook events to HookInstaller.events and EventKind: `PermissionRequest` (-> waiting on you),
  `PostToolUse` (-> working; clears "waiting on you" after the user answers a permission prompt),
  `StopFailure` (-> new status `.error`, label "error", reply = error text if present).
  Check the hook payload field names against https://code.claude.com/docs/en/hooks (WebFetch);
  stay tolerant of missing fields. Keep hooks `async: true`.
- Re-installing hooks must update existing installs (installer already dedupes by command — verify).
- `earshot doctor` should flag hooks as outdated when an event is missing and say
  `run: earshot install-hooks`.
- Render: `.error` row label "error". Finish sound must not play for PostToolUse.
- Tests for each transition, installer round trip, doctor outdated detection (pure part).

## Task 3 — iTerm2 support (experimental)

- `TerminalAdapter` protocol already exists (EarshotMac/TerminalAdapter.swift). Add `ITermAdapter`
  via NSAppleScript against application "iTerm2": list sessions (window index, tab index, tty, name),
  focus a session (select window/tab/session, activate), focused tty
  (`tty of current session of current tab of current window`, only when iTerm2 is frontmost).
  Parse output in EarshotCore with tests (like TerminalParse).
- Config `terminal`: `"auto"` (default: Apple Terminal + iTerm2 if running), `"terminal"`, `"iterm"`.
  A composite adapter merges tab lists and asks whichever app is frontmost for the focused tty.
- Never launch iTerm2 if it is not running (check NSRunningApplication bundle id `com.googlecode.iterm2`
  before any AppleScript).
- Doctor: Automation check for iTerm2 only when it is running.
- README: iTerm2 marked experimental (not tested on a real machine by the author).
